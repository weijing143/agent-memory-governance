# Semi-Automated Pattern / 半自动落地模式

> 配套 SKILL.md「Tailoring Modes」。当管线存在无人值守自动化（cron 治理、自动归档、后台 curator）时，本参考给出可直接借鉴的最小实现。人审制部署不需要本文。

## 1. 什么时候算"半自动"

只要满足任意一条，就应按半自动模式保留全部防御规则：

- cron / 定时器会在无人确认时移动、归档、升级或删除数据；
- 后台 curator 会自动合并重复、推进保留周期、清理过期；
- 归档候选可在用户离线时被批量执行（哪怕事后通知）。

反例（仍是人审制）：脚本只**生成候选清单**、不执行任何写/删/移动，等用户看到后逐条确认。

## 2. 核心机制：冲突阻塞 + 宽限期

半自动管线必须避免"自动选最新"。建议用**状态字段 + 宽限期**：

```
状态机（每条归档/记忆条目）：
  candidate  ──(宽限期 T1，无异议)──▶  archived
  candidate  ──(检测到冲突)─────────▶  blocked（等待裁决，不自动处理）
  archived   ──(保留期 T2 到期)─────▶  pending_delete
  pending_delete ──(宽限期 T3，无撤销)──▶ deleted（经确认执行器）
  blocked/pending_delete ──(用户撤销)──▶ 回到上一稳定状态
```

- `blocked`：检测到与活跃记忆冲突、或同主题在多区有不同主张时进入。**绝不在 blocked 状态下自动升级或覆盖**。
- 宽限期 T1/T3 给用户撤销窗口；T2 是归档保留期（SKILL 要求"保留周期必须显式"）。
- 所有状态转移写审计行（时间、触发原因、执行器），不可静默。

## 3. 最小冲突检测示例

冲突不必复杂，以下信号足够触发 `blocked`：

1. **跨区同主题不同主张**：同一关键标记（版本号、路径、专名）在活跃记忆与归档里的值不一致；
2. **快照过旧的易变事实**：带 `@YYYY-MM` 的版本/配额/状态，快照日期早于阈值（如 90 天）；
3. **重复条目**：同一事实在多个活跃文件出现，或活跃记忆与归档高度重叠；
4. **删除目标仍被引用**：拟删条目被其他文件的相对路径/链接引用。

参考检测逻辑（伪代码，与运行时无关）：

```bash
# 信号 1：跨区值冲突
for marker in $(list_tracked_markers); do
  active=$(extract_value active_memory "$marker")
  archive=$(extract_value reference_archive "$marker")
  [ -n "$active" ] && [ -n "$archive" ] && [ "$active" != "$archive" ] \
    && block "$marker: active=$active archive=$archive"
done

# 信号 2：快照过旧
grep -oE '@20[0-9]{2}-[0-9]{2}' active_memory | while read d; do
  age_days=$(( ( $(date +%s) - $(date -d "${d#@}" +%s) ) / 86400 ))
  [ "$age_days" -gt 90 ] && block "stale snapshot $d ($age_days d)"
done
```

## 4. 回滚预案

每次自动写/删/移动前，先做可逆准备：

- **移动/归档**：先复制到目标，验证目标存在且内容完整，再删除源（禁止 `mv` 后不验证、禁止失败回退到 `rm -f`）；
- **删除**：优先进入系统回收站（如 `gio trash`）或专用软删区，保留 N 天后才真删；真删前校验文件确实在软删区；
- **覆盖活跃记忆**：把旧条目全文写入旧记忆归档（tombstone：原条目+原因+取代者+日期+复用线索）后再覆盖；
- **失败即停**：任何一步失败，停止后续自动动作，产出报告交用户，不尝试第三种绕路方案。

## 5. 审计与验证

- 每个自动动作写一行 JSON 日志：`{ts, action, target, from_state, to_state, reason, executor}`；
- 运行结束产出 manifest：本次动了哪些文件、哪些被 block、哪些待确认；
- 声称"已删除"前必须验证（目标在回收站/确实不可读）；无法访问真实删除接口时只出报告，不谎称删除。

## 6. 与人审制的边界

本参考不要求人审制部署实现状态机。若你的所有写/归档/删都经用户当场确认，保留 SKILL 核心四条即可（三区隔离、直接展示矛盾、先归档后删除、明确确认）——**人就是冲突解决机制**。只有当自动化能在无人确认时改变数据，才需要本文的阻塞、宽限、回滚、审计。
